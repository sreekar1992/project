# ECG clinical research platform architecture

## Scope and status

The ECG clinical platform is a separate, tenant-aware application beside the existing local `ecg-gui` workbench. It is a **research and clinician-review workflow**, not an autonomous diagnostic, triage, prescribing, or treatment-recommendation system. A qualified clinician must review each model result before it can be documented as a clinical assessment.

The implementation is a modular Flask monolith. It keeps the existing, real waveform classifier behind an adapter instead of copying or simulating predictions. The current design is suitable for local development and research demonstrations; it is not a claim of production, regulatory, privacy, or clinical-validation readiness.

## Components

```text
React + TypeScript client
          |
          | HTTPS /api/v1 (Bearer access token)
          v
Flask clinical API ── SQLAlchemy ── PostgreSQL (Compose) / SQLite (local development)
          |                     |
          |                     +-- Alembic schema revisions
          |
          +-- private object storage (S3-compatible endpoint: AWS S3, MinIO,
          |   or OCI Object Storage S3 compatibility; local files in development)
          |
          +-- ECGModelAdapter ── existing raw-waveform parser, preprocessing,
          |                       RAMNV2 checkpoint, and Grad-CAM
          |
          +-- optional Redis + RQ worker for analysis jobs
```

The React client in `frontend/` uses React Router, TanStack Query, React Hook Form, Zod, and Material UI. Its ECG viewer receives only an authorized single-lead waveform through the API and supports in-browser zoom/pan; Grad-CAM is fetched through a bearer-protected image route. The API application factory is `ecg_cvd.clinical.app:create_app`; the legacy public workbench remains `ecg_cvd.gui` and is not exposed by the clinical API image.

## Request and workflow boundary

1. A user authenticates, receives a short-lived access token, and is resolved to a server-side principal.
2. Route permissions and tenant checks run before a service accesses a record.
3. The service creates or retrieves patients, encounters, ECG assets, analyses, reviews, reports, and audit events.
4. ECG bytes are stored outside the relational database. The database holds opaque object references, hashes, metadata, and workflow state.
5. The AI adapter validates and analyzes the real uploaded waveform. It records the model version and uncalibrated model score.
6. A clinician may create the assessment, diagnosis record, note, prescription record, and report. None are generated by the classifier.

Organization ownership is carried by clinical rows and enforced in `ClinicalService`. A patient account is additionally constrained to its linked patient record. The service returns a `404` for a cross-tenant patient lookup where practical to avoid patient discovery.

## Runtime paths

- **Synchronous analysis:** the API stores an analysis and invokes the adapter in-process. This is the default local behavior.
- **Asynchronous analysis:** with `ASYNC_ANALYSIS=true` and `REDIS_URL`, the API enqueues an analysis identifier in RQ. The waveform bytes remain in private object storage; Redis receives no ECG payload.
- **Reporting:** a clinician review creates or updates a diagnostic-report record. PDF generation then reads authorized records and writes a private PDF asset.

## Deliberate boundaries

- The model consumes numerical `.mat` or `.csv` waveforms, not ECG screenshots.
- The platform does not connect to a live hospital EHR, device gateway, pharmacy, identity provider, or national patient registry.
- FHIR output is a small read-only compatibility mapping, not a FHIR server or conformance statement.
- Feature and organization-override tables exist, but route-level feature-flag enforcement is not yet implemented.
- `k8s/platform/` supplies platform API/worker manifests and ConfigMap/Secret templates; they are unvalidated deployment scaffolding and have not been applied to a cluster. Legacy workbench manifests stay under `k8s/base`.
